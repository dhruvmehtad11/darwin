# Build System

The build system transforms service submodules into Docker images using a standardized pipeline.

---

## Prerequisites

Before running `setup.sh`, you must run `init.sh` to configure which services to enable:

```bash
sh init.sh    # Interactive wizard - creates .setup/enabled-services.yaml
```

---

## Build Pipeline Overview

```
.setup/enabled-services.yaml   services.yaml        setup.sh
          │                        │                    │
          │  User selections       │  Available apps    │  For each enabled service
          └────────────────────────┴───────────────────▶├──────────────────────────▶
                                                        │
                                                        │  1. Build applications
                                                        │  2. Build Ray images
                                                        │  3. Pull/push datastores
                                                        │  4. Pull/push operators
```

---

## Entry Point: setup.sh

**Location**: `setup.sh`

**What it does**:
1. **Checks** for `.setup/enabled-services.yaml` (exits if missing)
2. Initializes git submodules
3. Creates Kind cluster (if ENV=local)
4. Starts local Docker registry
5. Builds base images (Java, Python, Go)
6. Builds **enabled** applications from config
7. Builds **enabled** Ray runtime images (auto-enabled with darwin-compute)
8. Builds **enabled** Serve runtime images (auto-enabled with ml-serve-app)
9. Pulls/pushes **enabled** datastore images to local registry
10. Pulls/pushes operator images to local registry

**Key flags**:
```bash
sh setup.sh        # Interactive mode
sh setup.sh -y     # Auto-yes to all prompts
```

**Generated output**: `config.env` with:
```bash
DOCKER_REGISTRY=127.0.0.1:32768
KUBECONFIG=./kind/config/kindkubeconfig.yaml
```

## Configuration Files

### services.yaml (Available Services)

**Location**: `services.yaml`

Defines all available applications, datastores, and operators:

```yaml
applications:
  - application: darwin-compute        # Image name
    base-path: darwin-compute          # Code directory
    path: .                            # Build context within code directory
    base-image: darwin/python:3.9.7-pip-bookworm-slim
    enabled: true                      # Default state (can be overridden)
    env:                               # Build-time env vars
      - name: VAULT_SERVICE_MYSQL_USERNAME
        value: "root"

ray-images:
  - image-name: ray:2.37.0
    dockerfile-path: darwin-compute/runtimes/cpu/New-Lightweight/Ray2.37_Py3.10
    registry: localhost:5000

serve-images:
  - image-name: serve-md-runtime:latest
    dockerfile-path: ml-serve-app/runtime/darwin-serve-runtime
    registry: localhost:5000

datastores:
  - name: mysql
    image: mysql
    tag: "8.0"
    enabled: true
  - name: cassandra
    image: cassandra
    tag: "5.0"
    enabled: false
  - name: localstack
    image: localstack/localstack
    tag: "latest"
    enabled: true

operators:
  - name: kuberay-operator
    image: quay.io/kuberay/operator
    tag: "v1.1.0"
    enabled: true
  - name: nginx
    image: nginx
    tag: "1.27.4"
    enabled: true
  - name: grafana
    image: grafana/grafana
    tag: "latest"
    enabled: true
```

### .setup/enabled-services.yaml (User Selections)

**Location**: `.setup/enabled-services.yaml`

Generated by `init.sh`, contains user's selections:

```yaml
applications:
  darwin-ofs-v2: true
  darwin-mlflow: false
  darwin-compute: true
  darwin-cluster-manager: true
  darwin-workspace: false
  ml-serve-app: true

ray-images:
  "ray:2.37.0": true    # Auto-enabled with darwin-compute

serve-images:
  "serve-md-runtime:latest": true  # Auto-enabled with ml-serve-app

datastores:
  mysql: true
  cassandra: false
  kafka: true
  localstack: true
  opensearch: true
```

**Note**: `setup.sh` reads enabled status from `.setup/enabled-services.yaml`, NOT from `services.yaml`.

## Base Images

**Location**: `deployer/images/`

Three base images are built first:

| Image | Directory | Purpose |
|-------|-----------|---------|
| `darwin/java:11-maven-bookworm-slim` | `deployer/images/java-11/` | Java services (Feature Store) |
| `darwin/python:3.9.7-pip-bookworm-slim` | `deployer/images/python-3.9.7/` | Python services (MLflow, Compute) |
| `darwin/golang:1.18-bookworm-slim` | `deployer/images/golang-1.18/` | Go services (Cluster Manager) |

Each has a `build.sh` that runs `docker build`.

## Image Builder Script

**Location**: `deployer/scripts/image-builder.sh`

**Arguments**:
```bash
-a  application name
-p  path within submodule
-t  base-path (submodule directory)
-e  base image
-r  registry URL
-B  extra environment variables (pipe-separated)
```

**What it does**:
```bash
1. cd $base_path
2. rm -rf $path/target && mkdir $path/target/$application/.odinst
3. bash .odin/$application/build.sh      # Run submodule's build
4. cp -r .odin/$application/. $path/target/$application/.odin
5. docker build -f deployer/images/Dockerfile
6. docker tag & docker push to registry
```

## Generic Dockerfile

**Location**: `deployer/images/Dockerfile`

```dockerfile
ARG BASE_IMAGE=debian:bookworm-slim
FROM ${BASE_IMAGE} AS base

ARG APP_NAME
ARG APP_BASE_DIR
ARG APP_DIR
ARG EXTRA_ENV_VARS
WORKDIR /app/

# Copy build artifacts
COPY ${APP_BASE_DIR}/${APP_DIR}/target/${APP_NAME}/. /app/

# Make scripts executable
RUN chmod +x /app/.odin/*.sh 2>/dev/null || true

# Run setup.sh at build time (installs dependencies)
ENV BASE_DIR=/app
ENV DEPLOYMENT_TYPE=container
RUN if [ -f "/app/.odin/setup.sh" ]; then \
      env $(echo ${EXTRA_ENV_VARS_FINAL} | tr '|' ' ') bash -x /app/.odin/setup.sh; \
    fi

# Entrypoint runs start.sh at container startup
ENTRYPOINT ["bash", "-c", "/app/.odin/start.sh"]
```

## .odin Directory Convention

Each submodule MUST have `.odin/{service-name}/` with these scripts:

### build.sh
Compiles the application. Output goes to `target/`.

**Java example**:
```bash
#!/bin/bash
mvn clean package -DskipTests
cp target/*.jar target/$SERVICE_NAME/
```

**Python example**:
```bash
#!/bin/bash
pip install -r requirements.txt --target target/$SERVICE_NAME/
cp -r src/* target/$SERVICE_NAME/
```

### setup.sh
Runs at Docker build time. Installs runtime dependencies.

```bash
#!/bin/bash
# Install system packages
apt-get update && apt-get install -y curl

# Install Python dependencies
pip install -r /app/requirements.txt
```

### start.sh
Container entrypoint. Starts the service.

```bash
#!/bin/bash
cd /app
exec python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

### pre-deploy.sh (optional)
Runs before deployment. Used for DB migrations.

```bash
#!/bin/bash
python manage.py migrate
```

## Environment Variables at Build Time

Variables from `services.yaml` `env` section are passed to:
1. `docker build` via `--build-arg EXTRA_ENV_VARS`
2. `setup.sh` via env command

Format: `KEY1=VALUE1|KEY2=VALUE2|...`

## Ray Image Builder

**Location**: `deployer/scripts/ray-image-builder.sh`

Builds Ray runtime images separately:

```bash
-n  image name (e.g., ray:2.37.0)
-p  dockerfile path
-r  registry URL
```

**Note**: Ray images are automatically enabled when `darwin-compute` is selected in `init.sh`.

---

## Serve Image Builder

Uses the same `deployer/scripts/ray-image-builder.sh` script for serve runtime images:

```bash
-n  image name (e.g., serve-md-runtime:latest)
-p  dockerfile path (e.g., ml-serve-app/runtime/darwin-serve-runtime)
-r  registry URL
```

**Note**: Serve images are automatically enabled when `ml-serve-app` is selected in `init.sh`.

## Build a Single Service

To rebuild just one service:

1. Edit `.setup/enabled-services.yaml` - set only that service to `true`
2. Run:
```bash
source config.env
sh deployer/scripts/image-builder.sh \
  -a "darwin-compute" \
  -t "darwin-compute" \
  -p "." \
  -e "darwin/python:3.9.7-pip-bookworm-slim" \
  -r "$DOCKER_REGISTRY"
```

## Troubleshooting Builds

**Config not found**:
- Run `sh init.sh` first to create `.setup/enabled-services.yaml`

**Build fails in .odin/build.sh**:
- Check the submodule's build.sh for errors
- Ensure all dependencies are available

**Docker build fails**:
- Check if base image exists: `docker images | grep darwin/`
- Verify target/ directory has the build artifacts

**Push fails**:
- Ensure registry is running: `docker ps | grep registry`
- Check registry URL in config.env

**Datastore image pull fails**:
- Check internet connectivity
- Verify image name and tag in services.yaml
