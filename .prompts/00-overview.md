# Darwin Distribution - Project Overview

## What Is This Project?

Darwin Distribution is the **deployment orchestration layer** for the Darwin ML Platform. It does NOT contain service code - services live in git submodules. This project handles:

1. **Configuring** - Interactive selection of which services to enable
2. **Building** - Compiles submodules into Docker images
3. **Packaging** - Creates standardized container images
4. **Deploying** - Orchestrates Kubernetes deployment via Helm

## Key Files

| File | Purpose |
|------|---------|
| `init.sh` | **First step** - Interactive wizard to select services |
| `.setup/enabled-services.yaml` | User's service selections (generated by init.sh) |
| `services.yaml` | **Source of truth** - defines all applications, datastores, operators |
| `setup.sh` | Creates Kind cluster, builds Docker images, pulls datastore/operator images |
| `start.sh` | Deploys platform to Kubernetes via Helm with config overrides |
| `k8s-setup.sh` | Installs K8s operators (kuberay, prometheus) |
| `config.env` | Generated config with KUBECONFIG & DOCKER_REGISTRY |
| `pre-deploy.sh` | Runs DB migrations before deployment |

## Services Registry (services.yaml)

```yaml
applications:
  - application: darwin-ofs-v2          # Feature Store (Java)
  - application: darwin-mlflow          # MLflow (Python)
  - application: darwin-compute         # Compute orchestration (Python)
  - application: darwin-cluster-manager # Cluster management (Go)
  - application: darwin-workspace       # Workspace service (Python)
  - application: chronos                # Scheduling (Python)

ray-images:
  - image-name: ray:2.37.0              # Ray runtime images (auto-enabled with compute)

datastores:
  - name: mysql                         # Database images
  - name: cassandra
  - name: kafka
  - name: localstack
  - name: opensearch

operators:
  - name: kuberay-operator              # Operator images
  - name: nginx
  - name: grafana
```

Each application entry specifies:
- `application`: Image name
- `base-path`: Submodule directory
- `path`: Build context within submodule
- `base-image`: Parent Docker image (Java/Python/Go)
- `enabled`: Default enabled state
- `env`: Build-time environment variables

## User Configuration (.setup/enabled-services.yaml)

Generated by `init.sh`, this file stores user's service selections:

```yaml
applications:
  darwin-ofs-v2: true
  darwin-mlflow: false
  darwin-compute: true
  # ...

ray-images:
  "ray:2.37.0": true    # Auto-enabled if darwin-compute is enabled

datastores:
  mysql: true
  cassandra: false
  kafka: true
  # ...
```

**Note**: Ray images are automatically enabled when `darwin-compute` is selected.

## Submodule Structure

Each service submodule MUST have an `.odin/` directory:

```
service-submodule/
├── .odin/
│   ├── {service-name}/
│   │   ├── build.sh    # Compiles the application
│   │   ├── setup.sh    # Container initialization (runs at build)
│   │   ├── start.sh    # Container entrypoint (runs at runtime)
│   │   └── pre-deploy.sh  # DB migrations (optional)
│   └── ...
├── src/
└── ...
```

## Deployment Flow

```
1. sh init.sh          # ONE-TIME: Select services via interactive prompts
   └── Creates .setup/enabled-services.yaml

2. sh setup.sh
   ├── Check .setup/enabled-services.yaml exists
   ├── git submodule update --init --recursive
   ├── Create Kind cluster (if local)
   ├── Start Docker registry (localhost:5000)
   ├── Build base images (Java, Python, Go)
   ├── For each ENABLED application in config:
   │   ├── Run .odin/{service}/build.sh
   │   ├── docker build with deployer/images/Dockerfile
   │   └── docker push to registry
   ├── Build Ray images (if enabled)
   ├── Pull/tag/push ENABLED datastore images to local registry
   └── Pull/tag/push operator images to local registry

3. sh start.sh
   ├── Check .setup/enabled-services.yaml exists
   ├── Verify cluster connectivity
   ├── Run k8s-setup.sh
   │   ├── Install kuberay-operator (from local registry)
   │   ├── Install nginx-proxy-server (from local registry)
   │   └── Install kube-prometheus-stack (from local registry)
   └── helm upgrade --install darwin ./helm/darwin
       ├── --set overrides based on .setup/enabled-services.yaml
       ├── Deploy ENABLED datastores (MySQL, LocalStack, etc.)
       ├── Run health check job
       └── Deploy ENABLED services (Feature Store, MLflow, etc.)
```

## Environment Variables

After running `setup.sh`, `config.env` contains:

```bash
DOCKER_REGISTRY=127.0.0.1:32768   # Local registry port
KUBECONFIG=./kind/config/kindkubeconfig.yaml
```

All scripts source this file for configuration.

## Quick Commands

```bash
# First-time setup
sh init.sh                  # Configure which services to enable
sh setup.sh -y && sh start.sh

# Reconfigure services
sh init.sh                  # Re-run to change selections
sh setup.sh -y && sh start.sh

# Check deployment status
kubectl get pods -n darwin

# View logs
kubectl logs -n darwin deployment/darwin-{service-name}
```
